# Story 15.1: Forest topology discovery and ForestProvider scaffold

## Status: Done

## Story

**As a** DSPanel developer,
**I want** a `ForestProvider` that discovers every domain partition in the forest at connect time and holds one pooled LDAP connection per partition,
**so that** downstream services can fan out read and write operations to the correct partition without each call site re-implementing the discovery and connection bookkeeping.

## Acceptance Criteria

1. New service module `src-tauri/src/services/forest.rs` exposes `ForestTopology { partitions: Vec<DomainPartition> }` and `DomainPartition { distinguished_name: String, dns_name: String, netbios_name: Option<String>, default_dc_fqdn: Option<String> }`.
2. A new method `DirectoryProvider::discover_forest(&self) -> Result<ForestTopology>` reads `CN=Partitions,CN=Configuration,<base_dn>` with filter `(&(objectClass=crossRef)(systemFlags:1.2.840.113556.1.4.803:=2))` and collects `nCName` (partition DN), `dnsRoot`, `netbiosName`. The bit `0x00000002` of `systemFlags` is `FLAG_CR_NTDS_DOMAIN`, which excludes Schema, Configuration, and the *DnsZones partitions. The trait method ships with a default implementation that synthesizes a single-partition `ForestTopology` from `self.base_dn()` and `self.domain_name()`, so existing `DirectoryProvider` implementations (`DemoDirectoryProvider`, `MockDirectoryProvider` used by `tests/*.rs`) keep compiling without modification. Implementations that wish to expose the real forest topology override the default.
3. New struct `ForestProvider { partitions: HashMap<DnsName, Arc<dyn DirectoryProvider>>, seed_dns_name: String, partition_status: Mutex<HashMap<DnsName, ConnectionStatus>> }` is returned by a factory function `ForestProvider::connect(seed_provider: Arc<LdapDirectoryProvider>, auth_mode: LdapAuthMode, tls_config: LdapTlsConfig) -> Result<Self>`. The seed provider is the existing single-domain provider used for the initial bind and stays connected; additional `LdapDirectoryProvider` instances are constructed and bound for every other partition discovered.
4. `ForestProvider` implements `DirectoryProvider`. Method bodies fan out to per-partition providers as appropriate. `is_connected()` returns true when the **seed** partition is connected. Non-seed partition states (Connected / Reconnecting / Unreachable) are exposed via `partition_status()` and consumed by the partial-failure banner in Story 15.6, but do NOT gate the global `is_connected()` value. Without this, a single offline non-seed DC would put the entire UI into the disconnected state, contradicting the partial-failure design. `domain_name` reports the seed partition's DNS name. `base_dn()` returns the DN of the partition whose `nCName` equals the seed DC's RootDSE `rootDomainNamingContext` attribute (the forest root partition). When the seed is itself a forest root, this is the seed partition's DN. The rule is documented in `services/forest.rs::ForestProvider::base_dn` so callers querying `CN=Configuration,<base_dn>` keep working.
5. Each per-partition `LdapDirectoryProvider` keeps its existing single-connection pool. `ForestProvider` does NOT introduce a global mutex; the per-partition pools serialize their own connection state.
6. Connection failures on non-seed partitions are non-fatal at construction time. A partition that fails to bind is recorded in `partition_status` with `ConnectionStatus::Unreachable(classification)` and `ForestProvider::partition_status() -> Vec<(DnsName, ConnectionStatus)>` exposes the table for the partial-failure banner (Story 15.6).
7. The seed partition failing IS fatal: `ForestProvider::connect` returns the error from the seed `LdapDirectoryProvider::test_connection` so the existing connection error UX (Story 1.2) is unchanged.
8. Unit tests cover (a) parsing of a stub `crossRef` entry list to a `ForestTopology`, (b) the `systemFlags` bitwise filter rejects Schema, Configuration, ForestDnsZones, DomainDnsZones, (c) `partition_status()` reporting after a simulated mid-construction bind failure on a non-seed partition.
9. `DirectoryEntry` gains an `Option<String> partition_dns_name` field with `#[serde(skip_serializing_if = "Option::is_none")]` and the camelCase name `partitionDnsName` on the wire. The field is added in this foundation story so Story 15.2 can populate it during browse fan-out and Story 15.4 can read it for the partition badge. Default value at construction time is `None`; only the fan-out paths in 15.2 / 15.3 populate it. The frontend `DirectoryEntry` type in `src/types/directory.ts` and every `mapEntryTo*` helper expose the field as `partitionDnsName?: string`.
10. A new React context `ForestContext` (`src/contexts/ForestContext.tsx`) is created in this story. It exposes `forestTopology: ForestTopology` (fetched once at app start via a new `get_forest_topology` Tauri command), `partitionStatus: Record<DnsName, ConnectionStatus>` (subscribed via the `forest-status-changed` Tauri event introduced in Story 15.6 - the context tolerates the event being unimplemented in 15.1 by treating every partition as Connected), and a derived `isSingleDomainForest: boolean`. The context is the single source of truth for the 'hide multi-domain UI in single-domain forests' rule referenced by stories 15.2 (Domain column), 15.4 (partition badge), and 15.6 (banner).
11. Per-partition `test_connection` calls during `ForestProvider::connect` execute concurrently via `tokio::join_all` and each carries a per-call timeout of 3 seconds (configurable via `DSPANEL_PARTITION_BIND_TIMEOUT`). A safety cap of 50 partitions limits the discovery output before any bind attempts; if `discover_forest` returns more, the loader logs `tracing::warn!` and truncates to 50 with the seed kept first. These bounds keep the seed-login latency under NFR1 (3s startup) regardless of forest size.

## Dev Notes

### Architecture

DSPanel currently has one `Arc<dyn DirectoryProvider>` in `AppState`, which is `LdapDirectoryProvider` (or `DemoDirectoryProvider`). Story 15.1 replaces that single provider with a `ForestProvider` *that itself implements* `DirectoryProvider`, so the rest of the codebase keeps consuming `state.provider()` as today. The replacement is a structural decorator: `ForestProvider` wraps N `LdapDirectoryProvider` instances and dispatches.

The per-partition provider isolation matters for two reasons:

1. **Authentication state**: each partition needs its own bind. With GSSAPI (Kerberos), the bind is per-DC; the same TGT can be reused but the SASL/GSSAPI state is connection-scoped. Sharing a connection across partitions is technically possible only if the DCs are GCs, but DSPanel doesn't assume GC.
2. **Connection pool reuse**: `LdapDirectoryProvider` already has battle-tested logic for connection age, idle timeout, retry on stale connection, RODC detection. We reuse it as-is, once per partition.

### Why this story is the foundation

Stories 15.2 (browse), 15.3 (search), 15.4 (route by DN) and 15.5 (write routing) all need (a) the topology, (b) the partition map, (c) the `route_for_dn` helper. Splitting this story isolates the structural change from the call-site changes and lets QA validate the foundation before the fan-out code lands.

### Stub topology for tests

```rust
// fixture
let entries = vec![
    crossref_entry("DC=corp,DC=example,DC=com", "corp.example.com", "CORP", system_flags=2),
    crossref_entry("DC=eu,DC=corp,DC=example,DC=com", "eu.corp.example.com", "CORPEU", system_flags=2),
    crossref_entry("CN=Schema,CN=Configuration,DC=corp,DC=example,DC=com", "", "", system_flags=1),
    crossref_entry("CN=Configuration,DC=corp,DC=example,DC=com", "", "", system_flags=1),
    crossref_entry("DC=ForestDnsZones,DC=corp,DC=example,DC=com", "", "", system_flags=1),
];
let parsed = parse_partitions_from_entries(&entries).unwrap();
assert_eq!(parsed.len(), 2);
assert_eq!(parsed[0].dns_name, "corp.example.com");
assert_eq!(parsed[1].dns_name, "eu.corp.example.com");
```

### Project structure note

The new module lives under `services/`, not `models/`, because it owns connection bookkeeping and a typed Tauri-state-friendly surface. Mirror the layout of `services/ldap_directory.rs` (single file, tests at the bottom in `mod tests`). The integration tests for the topology parser go to `src-tauri/tests/forest_topology.rs` so they can use `LdapDirectoryProvider`'s public `search_configuration` API end-to-end against a future demo provider, mirroring the pattern of `tests/replication.rs`.

### Wiring in lib.rs

`AppState::new` currently constructs an `LdapDirectoryProvider`. The change: construct the seed provider, then `ForestProvider::connect(seed, ...)`, store the result as `Arc<dyn DirectoryProvider>` in the state. Demo mode: `ForestProvider::connect_demo(demo_provider)` returns a `ForestProvider` with one entry whose key is `"demo.local"` so the demo path keeps a single-domain shape end-to-end without conditionals downstream.

### MockDirectoryProvider compatibility

The `MockDirectoryProvider` defined in `services/directory.rs::tests` (and reused across `tests/*.rs`) does not need source modifications for Story 15.1. The `discover_forest` trait method ships with a default implementation that synthesizes a single-partition `ForestTopology` from `self.base_dn()` and `self.domain_name()`. Any test fixture that wants to exercise multi-partition behavior can override the method explicitly (the new `DemoForestProvider::connect_multi_partition` fixture is the canonical example). This preserves the existing 1700+ cargo tests untouched.

### Single-domain UX rule

When `forestTopology.partitions.length === 1` the multi-domain UI affordances (Domain column in lookup tables, `<DomainBadge>` in detail headers, `<ForestStatusBanner>`, AuditLog Domain filter) are hidden. The `<ForestContext>::isSingleDomainForest` derived flag is consumed by every component that needs the rule. This is documented here once and referenced from stories 15.2, 15.4, 15.6.

### Completion Notes List

- Discovery is rooted at `configurationNamingContext` (read from the rootDSE together with `rootDomainNamingContext`), not at `CN=Configuration,<defaultNamingContext>`: on a child-domain DC the latter does not exist. Falls back to the base-DN form when the rootDSE attribute is missing.
- `ForestProvider::connect` treats a seed `test_connection` returning `Ok(false)` as an error carrying the classification key (AC #7). Both callers (`lib.rs` setup and `connect_simple_bind`) fall back to `ForestProvider::single_partition(seed)`, so the existing connection-error UX is unchanged and startup never aborts on a directory problem.
- Non-seed partition DCs are located through the existing DNS SRV resolution on the partition `dnsRoot` (`LdapDirectoryProvider::new_for_partition`, no server override). A DN-shaped simple-bind identity is rejected by DCs of other domains (AD requires a UPN or NT name there); such partitions land in `partition_status()` as `Unreachable(<classification>)` and do not block the seed. GSSAPI and UPN simple binds fan out normally.
- `tokio::join_all` named in AC #11 does not exist; concurrency uses `tokio::task::JoinSet` with `tokio::time::timeout`, no new dependency.
- `PartitionConnector` is the seam that lets tests script per-partition outcomes (AC #8c, AC #11 timeout and cap tests) without a mockable `LdapDirectoryProvider`; production uses `LdapPartitionConnector`. The cap test asserts truncation and seed ordering; the `tracing::warn!` emission is not captured (no tracing test subscriber in the crate).
- `base_dn()` on the forest now returns the forest root DN when the rootDSE exposed it (AC #4). For a child-domain seed this changes what callers that build per-domain containers from `provider.base_dn()` (GPO viewer `CN=Policies,CN=System`, OU tree root) resolve to; Story 15.4 routes those by DN. Single-domain forests are unaffected (root == seed).
- Demo mode wraps `DemoDirectoryProvider` through `ForestProvider::single_partition`, keyed by the demo provider's own identity (`contoso.com`) rather than the `demo.local` placeholder from the Dev Notes, so the topology and the status bar agree.
- Forest assembly runs inside the Tauri `setup` hook right after permission detection, bounded by the per-partition timeout (3 s, `DSPANEL_PARTITION_BIND_TIMEOUT`) and the 50-partition cap. Single-domain forests pay one extra `CN=Partitions` search.
- `AppState` keeps a typed `Arc<ForestProvider>` next to the `Arc<dyn DirectoryProvider>` (`set_forest` / `forest`) so `get_forest_topology` and the Story 15.6 status commands reach the forest without downcasting; `set_provider` clears it.
- `DirectoryEntry.partition_dns_name` is `#[serde(default, skip_serializing_if = "Option::is_none")]`; the 81 struct-literal sites were updated mechanically. Frontend `DirectoryEntry` and every `mapEntryTo*` result expose `partitionDnsName?: string`.
- `ForestContext` re-fetches the topology whenever the seed `isConnected` flag flips (login prompt, reconnect) and tolerates an undefined command result (App tests mock unknown commands as `undefined`).
- The locale JSON files and `translations.test.ts` were not Prettier-clean on `main`; formatted in a separate `chore(ui)` commit.
