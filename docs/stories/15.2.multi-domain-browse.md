# Story 15.2: Multi-domain browse with domain column

## Status: Draft

## Story

**As an** AD operator working in a multi-domain forest,
**I want** the user / computer / group / contact lookup lists to show objects from every domain in the forest, with a clear indication of which domain each object lives in,
**so that** I can find an account regardless of which domain hosts it and visually disambiguate two objects that share a name across domains.

## Acceptance Criteria

1. The four backend `browse_users_inner` / `browse_computers_inner` / `browse_groups_inner` / `browse_contacts_inner` functions in `commands/directory.rs` are rewritten to fan out to every `ForestProvider` partition concurrently and merge the results.
2. `DirectoryEntry` gains a `partition_dns_name: Option<String>` field populated by the partition that returned the entry. Serialization is camelCase `partitionDnsName`; the field is optional on the wire to keep deserialization compatible with old persisted snapshots.
3. The merge logic concatenates per-partition results, sorts by `display_name` case-insensitive (current sort), and applies the existing `BrowseResult` pagination over the merged list. The cache TTL (60s) and `MAX_BROWSE` cap (5000) become *per partition*, not global.
4. A partition that fails to respond does NOT abort the browse: its results are absent and `BrowseResult` carries a new `failed_partitions: Vec<String>` field listing the DNS names of partitions whose query errored. The seed partition failing is still surfaced as an error to the caller.
5. Frontend lookup pages (`UserLookup`, `ComputerLookup`, `GroupManagement`, `ContactLookup`) gain a "Domain" column rendered with the value of `partitionDnsName`. The column is sortable and filterable. In a single-domain forest the column is hidden.
6. The `useBrowse` hook surfaces `failedPartitions` so the lookup pages render a non-blocking warning banner ("Could not reach 1 of 3 domains: corp-east.example.com - retry") above the list.
7. Per-partition cache invalidation: `state.browse_cache` (and its three siblings) becomes `HashMap<DnsName, (Instant, Vec<DirectoryEntry>, bool)>` so a partial refresh of one partition does not invalidate the others.
8. Unit tests cover (a) merge ordering, (b) partial-failure path with one partition erroring, (c) per-partition cache hit / miss matrix, (d) the seed-partition-fails error path.

## Dev Notes

### Pagination semantics in a fan-out world

The existing `BrowseResult` pagination is page-based (`page * page_size`) over a sorted, capped result set. Story 15.2 keeps the same shape and applies pagination *after* the merge. This means a forest with 3 partitions of 1000 users each (3000 total) paginates over all 3000 in one virtual list. The cache stores per-partition arrays; the merge happens on every `browse_*_inner` call (cheap, < 1ms for 5000 items) so a per-partition refresh stays granular.

### Partial failure tolerance

The rule "fail one partition, keep the others" is the explicit choice. Alternatives considered:

- *Hard fail on any partition error*: simple, but turns a transient network blip on a remote DC into a complete browse outage. Rejected.
- *Auto-retry per partition with backoff*: hides the failure from the operator. Rejected because audit operators need to know which partitions are stale.

The seed-partition-error special case keeps the connection-loss UX of 1.x intact: if your own domain is down, you have nothing to browse.

### Why `partitionDnsName` is `Option<String>`

For backward compatibility with persisted snapshots (Story 7.5) and audit entries (Epic 11) that predate this story. New emissions always populate it.

### Project structure note

The four `browse_*_inner` functions live in `src-tauri/src/commands/directory.rs`. Per repo convention, business logic stays *out* of command handlers when possible. For Story 15.2 the fan-out logic IS business logic; create a sibling helper module `src-tauri/src/services/forest_browse.rs` exposing `browse_users_across_forest`, etc., and let the command handler call it. This mirrors how Story 14.1 split `services/security_indicators.rs` from the Tauri commands.
