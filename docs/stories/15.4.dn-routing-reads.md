# Story 15.4: DN-based routing for read-detail commands

## Status: Draft

## Story

**As an** AD operator,
**I want** `UserDetail`, `ComputerDetail`, `GroupDetail`, and the various `read_entry` consumers (Story 8.x topology, Story 11.3 GPO viewer, etc.) to talk to the partition that hosts the DN they are inspecting,
**so that** opening a detail page on an object from any domain returns the live attributes, group memberships, security indicators (Epic 14), and snapshots without falling back to a partial picture.

## Acceptance Criteria

1. New helper `fn dns_domain_from_dn(dn: &str) -> Option<String>` extracts `dc=...` components and joins them with `.` to produce a DNS suffix (e.g. `CN=jdoe,OU=Users,DC=sub,DC=racine,DC=dmi` -> `sub.racine.dmi`).
2. `ForestProvider::route_for_dn(&self, dn: &str) -> Option<&Arc<dyn DirectoryProvider>>` returns the partition provider whose DN suffix is the longest match for the input DN. Partitions registered as `DC=sub,DC=racine,DC=dmi` outrank `DC=racine,DC=dmi` for DNs that live under `sub`. Falls back to the seed partition if no suffix matches. Tie-breaker on equal-length suffix matches: the partition whose `dns_name` sorts alphabetically first wins. The tie-breaker is deterministic for tests and documented inline in `route_for_dn`.
3. Every read-detail Tauri command that takes a DN (`get_user`, `get_user_by_dn`, `get_computer_by_dn`, `get_group_members`, `read_entry`, `get_user_groups`, `get_snapshot_history`, `evaluate_user_security_indicators`, `evaluate_computer_security_indicators`, etc.) uses `ForestProvider::route_for_dn` to pick the partition before delegating.
4. The `state.provider()` accessor returns the `ForestProvider` (as `Arc<dyn DirectoryProvider>`), keeping all 30+ command call sites working without per-callsite changes. Command handlers continue to call `provider.search_users(...)`, `provider.read_entry(...)`, etc.; the routing happens inside `ForestProvider`.
5. The `UserDetail` and `ComputerDetail` pages display the partition DNS name in the header via a new `<DomainBadge>` component (`src/components/common/DomainBadge.tsx`) under the display name. The badge uses the `<Tooltip>` component (1.1.1 standard) for the 'Domain: {{name}}' helper text, never native HTML `title=`. Visibility is gated on `<ForestContext>::isSingleDomainForest === false`.
6. Unit tests cover (a) `dns_domain_from_dn` against a battery of DN shapes including lowercase / mixed case `dc=` components, leading whitespace, and CNs containing literal commas escaped as `\,`, (b) longest-suffix match for nested partitions, (c) fallback to seed when no suffix matches.
7. Round-trip invariant test: for every `DirectoryEntry` returned by a forest fan-out path with `partition_dns_name = X`, `ForestProvider::route_for_dn(entry.distinguished_name)` returns the partition whose `dns_name == X`. The invariant is asserted in `tests/forest_routing.rs` against a multi-partition fixture.
8. Special DN cases routed deterministically: empty DN ('') and the rootDSE base scope route to the seed partition. DNs under `CN=Configuration,...` or `CN=Schema,...` route to the seed partition (these partitions are forest-shared and conventionally owned by the forest root, which the seed reaches). DNs that fail `dns_domain_from_dn` parsing (no `dc=` components) route to the seed partition with a `tracing::warn!` so the operator can inspect.

## Dev Notes

### Why longest-suffix match

In a forest with both `corp.example.com` and `eu.corp.example.com`, the DN `CN=alice,OU=Users,DC=eu,DC=corp,DC=example,DC=com` matches both partition base DNs as suffixes; the *correct* partition is the longer one (`DC=eu,DC=corp,DC=example,DC=com`). Naive shortest-match would route to the parent partition, fail with `noSuchObject`, and leave the operator confused.

### CN escaping in DNs

LDAP DNs allow embedded special characters via backslash escape: `CN=Doe\, John,OU=Users,DC=corp,...` is a single CN "Doe, John". The DN parser must respect the escape. We don't need a full RFC 4514 parser; a state machine that walks the DN and tracks `\` to skip the next character is enough. The `services::ldap_directory::ldap_escape` function already handles outbound escaping; inbound parsing for the suffix extractor is the new piece.

### Frontend single-domain UX

If the forest has exactly one partition, the partition badge is redundant and clutters the header. The "Domain" column in lookups (Story 15.2) follows the same rule. Both check `forestTopology.partitions.length > 1`, where the topology is fetched once at app start via a new `get_forest_topology` Tauri command and cached in a React context.

### Project structure note

The DN suffix helper lives in `services/forest.rs` next to the `ForestProvider`. The `<DomainBadge>` component lives in `src/components/common/DomainBadge.tsx` (alongside `<HealthBadge>`, `<StatusBadge>`, `<SecurityIndicatorDot>`). The forest topology React context lives in `src/contexts/ForestContext.tsx` (introduced in Story 15.1 AC #10).

### Tauri command -> routing decision table

Every `commands/*.rs` Tauri command that takes a DN argument falls into one of three buckets. This appendix is exhaustive at the time of Story 15.4 drafting; new commands added later inherit the same rules.

| Command (commands/*.rs) | Primary DN argument | Routing decision |
| --- | --- | --- |
| `get_user`, `get_user_by_dn` | user DN | DN-routed |
| `get_computer_by_dn` | computer DN | DN-routed |
| `get_group_members` | group DN | DN-routed |
| `read_entry` | object DN | DN-routed |
| `get_user_groups`, `get_nested_groups` | user DN | DN-routed |
| `get_snapshot_history` | object DN | DN-routed |
| `evaluate_user_security_indicators` | user DN | DN-routed |
| `evaluate_computer_security_indicators` | computer DN | DN-routed |
| `get_replication_metadata`, `get_replication_value_metadata` | object DN | DN-routed |
| `get_user_account_control`, `get_user_spns`, `get_cannot_change_password` | user DN | DN-routed |
| `get_all_attributes` | object DN | DN-routed |
| `get_thumbnail_photo` | user DN | DN-routed |
| `browse_users`, `browse_computers`, `browse_groups`, `browse_contacts`, `browse_printers` | (none) | fan-out (Story 15.2) |
| `search_users`, `search_computers`, `search_groups`, `search_contacts`, `search_printers` | (none) | fan-out (Story 15.3) |
| `get_user_by_identity` | sAMAccountName (not a DN) | fan-out, seed-first (Story 15.3) |
| `get_ou_tree` | (none) | fan-out, partition-grouped (Story 15.2) |
| `get_deleted_objects` | (none) | fan-out (Story 15.2) |
| `is_recycle_bin_enabled` | (none) | seed-only (forest-level feature flag) |
| `get_schema_attributes` | (none) | seed-only (schema partition is forest-shared) |
| `search_configuration` | (none) | configuration-partition-only (forest-shared via seed) |
| `discover_forest`, `get_forest_topology` | (none) | seed-only |
| `get_current_user_groups`, `authenticated_user`, `probe_effective_permissions` | (none) | seed-only (operator session) |
| `resolve_group_by_rid` | RID (partition-scoped) | fan-out + first-match-wins |
